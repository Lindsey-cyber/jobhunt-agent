## 目标（候选人原话的要点）
一个能完全自动投简历、她不用逐条检查就能信任的系统：多 agent 分层监督；中大型美国公司 New Grad / Entry-Level AI/ML 岗位规模化海投，小公司收集招聘线索供她外联。阶段：1a 搜全 → 1b 筛对 → 1c 投出；2 外联；3 跟进。

## 总 agent 的规则（Orchestrate，`.claude/skills/poteto-mode/playbooks/orchestrate.md`）
- 只决定、派活、读产出、打分；不写代码、不做具体工作。
- 每个任务书写明：目标、可写/不可写的路径、禁止的动作、证明完成的证据（命令 + 期望输出）。写不出证据 = 任务还没定义好。
- 每份产出由非作者、不同模型的审核者按证据核对；读 diff 和产物，不读工人的总结。审核通过才合入 `v2`。
- 先问"这个问题该不该存在"：能删掉问题就不去优化它；选最直接、最省 token 的做法。
- 只问候选人真正的产品决定或不可逆的事；合格标准、先后顺序、重试由总 agent 决定。
- 每个被发现的错误变成测试/检查，不靠第二次人工发现。
- **每一轮结束必须写复盘（一行进 decisions.tsv，phase=retro）**：目标数字动了多少；这一轮修的是"尺子"（测量方法）还是"东西本身"；有没有同类错误第二次出现（有 → 先写成统一的结构检查，再继续）。**连续两轮目标数字不收敛 → 停止派修复，回到前提重新设计**，不再开下一轮。
- 后台长任务（搜索、全量抓取）开跑前先问：跑完的结果会被用来做什么决定？说不出来就不跑。
