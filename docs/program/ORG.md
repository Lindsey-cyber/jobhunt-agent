# 组织章程（v3）

任何会话打开这个 repo，先读这份。这里是多 agent 架构的规则；`docs/REWRITE.md` 讲为什么这样设计。规则能写成检查的，都已经写成检查（见文末「谁在强制」），本文只是说明。

## 角色

- **总协调**：主会话。只做六件事：定目标和验收标准、切单元、写任务书、派工人或经理、验收、复盘。**不改代码，也不跑流水线拿数字**；需要一个数字，就派运营单元去跑。只有总协调写 `docs/program/` 和 `docs/decisions.tsv`。
- **经理**：某个领域同时进行的单元超过 3 个时才开，是一个持久的云端会话。它管这个领域的工人和任务书，交给总协调一份汇总（`docs/program/<领域>.md`），不转发工人的原始报告。层级最多三层。
- **工人**：一个单元一个，做完即弃。建造工人在独立的 git worktree 里改代码；运营工人只跑已合入的代码，写 `data/` 下的运行产物。
- **审核者**：不是作者，用另一个模型（作者 sonnet 就让 haiku 或 opus 审）。只读 diff、产物和原始材料，不读工人的总结。给出 PASS、ISSUES（列出能证明的全部问题）或 BLOCKED。

## 单元的生命周期

1. 总协调把任务书写进 `docs/program/kickoffs/<单元id>.md`，格式见 `kickoff-template.md`，必填各节由测试检查。
2. 工人在 worktree 里完成，提交到分支 `unit/<单元id>`，报告证据。
3. 审核者对当前 head 给出结论。
4. 总协调读 diff 并核对证据，通过后合入 `v3`。
5. 在 `scorecard.tsv` 记一行：单元、领域、角色、工人模型、审核模型、结论、返工次数、缺陷数。

## 轮次和复盘

- 一轮是同一个目标数字下的一批单元。每轮开始和结束各在 `rounds.tsv` 记一行：目标数字的前值和后值；这一轮修的是尺子（measure）还是东西本身（thing）；有没有重复出现的错误类。
- **目标数字连续两轮没有变好，就必须先记一行 `replan`，才能开下一轮。** 这条由测试强制。
- **同一类错误第二次出现**：停下这个领域的派活，先派一个结构单元（测试或类型），让这类错写不出来。
- 每个单元的任务书都写 token 预算，超出就停下，交回原因。
- 长任务开跑前，在任务书里写下「跑完要做什么决定」。写不出来就不跑。

## 省 token（候选人 2026-11-02：保证质量的前提下尽量省）

- 任务书写清楚文件路径，不贴代码；工人自己读，总协调不替它预读。
- 工人默认用 sonnet，机械性的活用 haiku；审核者默认用 haiku：跑证据命令，读 diff。只有涉及判断的单元（规则、身份、下架判定）才用 opus 审。
- 总协调验收只看 `git diff --stat`、证据命令的输出和关键的 diff 片段，不通读全部 diff。
- 不开探索型 agent 做「先看看」；不开 swarm；同一个领域并行超过 3 个单元才设经理。
- 一个新角色的第一个单元验收通过之前，不派同类的第二个。
- 给候选人的回复：先说有没有事要她决定，进展三五行。

## 信任等级（按角色）

| 等级 | 合入方式 | 升级 | 降级 |
|---|---|---|---|
| 0 | 审核者 PASS + 总协调读 diff | 连续 3 个单元首轮 PASS | — |
| 1 | 审核者 PASS + `npm run check` 绿，直接合入 | 连续 10 个单元无缺陷，且相关错误类都有结构检查 | 被退回 2 次 → 0，并换模型或缩小单元 |

提交申请的自动化不在这张表里，只有候选人能放开（`data/config.yaml`）。

## 目录归属

见 `owners.tsv`。工人只能写自己单元所在领域的路径。共享路径（`src/domain/`、`src/cli.ts`、`package.json`、`tests/structure.test.ts`、`tests/org.test.ts`）只归平台领域。

## 现在的目标（候选人 2026-11-02）

只做第 1 步「搜全」。最终交付一份名单：符合她规则、可以投的岗位。可投的判断以 `data/policy.yaml` 和 `src/discover/eligibility.ts` 为准。个性化问答以后再做。不要事无巨细地问她；只问她才能做的决定，或者撤不回的事。

## 谁在强制

| 规则 | 机制 |
|---|---|
| 总协调不改代码 | `.claude/hooks/coordinator-guard.sh`：主仓库里 `src/ tests/ scripts/ config/` 的 Edit 和 Write 一律拒绝；worktree 里不受影响 |
| 每个 src 目录只有一个主人 | `tests/org.test.ts` 读 `owners.tsv` |
| 任务书各节齐全 | `tests/org.test.ts` 读 `kickoffs/*.md` |
| 两轮不收敛必须先 replan | `tests/org.test.ts` 读 `rounds.tsv` |
| 评分卡格式 | `tests/org.test.ts` 读 `scorecard.tsv` |
