## 怎么跑

```bash
cd jobhunt-agent && npm ci
export JH_WORKDAY=off JH_RESOLVE=off   # JH_RESOLVE=off：OpenAI 额度已用完，不要在线起草
npm run -s jh -- apply-approved --limit 300 > .scratch/batchN.out 2>&1 &
```

- 输出每行一个结果：`confirmed`、`held (...)` 或 `error ...`。用 Monitor 盯着输出，过滤掉 `waiting for the account verification`。
- 每日上限是 `data/config.yaml` 里的 `dailySubmitCap: 100`，归候选人管，不要改。
- 跑完 `npm run -s jh -- reconcile`，把收到确认邮件的申请从 unconfirmed 改成 confirmed（需要配好 Gmail）。
- `npm run -s jh -- pending` 是给候选人看的每日清单。
- 停批：`kill -9` 进程号（`ps -eo pid,args | awk '/apply-approved/ && !/awk/ {print $1}'`）。不要用 `pkill -f`，它会把自己所在的 shell 也杀掉。

## 每轮的工作方式：边投边修

1. 看 `held (...)` 的原因，到 `data/runs/<岗位>/<时间>/plan.json` 里查这个字段的 `label`、`kind` 和 `options`。
2. 能从 profile、简历或她的已知回答推出来的，在 `src/plan/rules.ts` 加或扩一条规则，同时在 `tests/plan.test.ts` 加一条断言。规则按顺序匹配，**第一个 pattern 命中的规则就决定结果**；返回 `undefined` 时，后面的规则不会再试。label 会先经过 `normalize()`，它会去掉开头的 "Please select" 之类，可以用下面这个脚本（存成 `.scratch/which.mts`，再 `npx tsx .scratch/which.mts "<label>"`）查 normalize 的结果和命中了哪条规则：

   ```ts
   import { PROFILE_RULES } from "../src/plan/rules.ts";
   import { normalize } from "../src/plan/text.ts";
   const label = normalize(process.argv[2]!);
   console.log(JSON.stringify(label));
   for (const r of PROFILE_RULES) if (r.pattern.test(label)) console.log(r.path, String(r.pattern).slice(0, 160));
   ```
3. 只属于某家公司的问题，用原文写进 `data/answers.yaml`，注释写明依据。
4. "Why X?" 这类题：在线起草关掉了，就按简历手写，先用 `checkDraft`（`src/verify/grounding.ts`）核对每句话都有简历依据，再 `appendAnswer`（`src/store/answerlog.ts`）存进 `data/answers.jsonl`。写法可参照里面 `why:figma` 那条。
5. `npm run check` 全绿后再提交，推到 `v2`。改了规则后重启这一批，被卡住的岗位会排在没投过的后面自动重试。

**只能留给候选人的**（不要猜）：
- 犯罪记录
- 家人或熟人是医疗从业者、政府官员
- 简历里没写的工作年限
- 手写签名
- How did you hear 的选项里没有符合实际的
- 种族题没有"不愿透露"选项（Crowe）
